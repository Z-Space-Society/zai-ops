# ADR-0011: Signing keys are PEMs on the control node, rendered per service, rotated with scn-config

> Status: **Accepted** (2026-10-15).

## Context

Three services sign OAuth material with an asymmetric key, and each got its key
a different way:

- **Corliss** had two PKCS8 PEMs (an ES256 key for its atproto OAuth client, an
  RS256 key for its OIDC provider), each generated by an openssl `pipe` lookup
  in `group_vars/all/main.yml` and written to files on its CT.
- **The PDS** generated its own key on first boot and kept it in its key store
  under `/var/lib/pds`. An optional operator-supplied JWK set file
  (`pds_oauth_jwk_set`) could override it, and the staging cluster had one.
- **scn-chat**, being added, needs a JSON array of private JWKs. Its first
  draft generated one by cloning scn-chat and running `pnpm keys` on the
  control node, which has no Node, and cached an empty file when that failed.

None of them could be rotated. The PDS's key sat outside the Tier-1 backup,
in a data directory whose backup is still switched off.

## Decision

1. **The stored form is a PKCS8 PEM file under `/root/.zai-secrets`.** Per key
   name: `<name>.pem` is the current key and `<name>.previous.pem`, present
   only during a rotation, is the key going out. They ride the Tier-1 backup
   of that directory with every other secret.

2. **One lookup generates and reads them:**
   `query('signing_keys', '<name>')` (`ansible/lookup_plugins/signing_keys.py`)
   returns `[current]` or `[current, previous]`. It generates the current key
   when the file is absent (P-256, or 2048-bit RSA with `type='rsa'`), writes
   atomically at mode 0600, and fails on an empty or unparsable file instead
   of handing it on. `generate=false` makes a missing key an error. Values come
   back with trailing whitespace stripped, as the `pipe` lookup did, so moving
   Corliss onto it changed no byte on its CT.

3. **Services that take JWKs render the list with one filter:**
   `private_jwk` (`ansible/filter_plugins/jwk.py`). The current key goes first.
   The **kid is the RFC 7638 thumbprint** of the public key, the same rule
   Corliss and the PDS already used. A kid is a property of the key, so it
   cannot drift while the PEM is unchanged.

4. **ES256 on P-256 for every new key.** atproto requires it of OAuth clients.
   RSA exists only as Corliss's OIDC key, which Corliss reads as a PEM.

5. **Keys already in use are adopted, never regenerated.** Corliss's two files
   are the precedent and did not move. The pds role adopts whatever key the
   PDS signs with now: the first key of an operator-supplied
   `pds_oauth_jwk_set` where one exists (a second key becomes the previous
   key; `jwk_to_pem`), otherwise the server's own key, copied off its key
   store once (following the reference the server records, since older
   builds left orphaned keys beside it; `didkey_to_pem`). It supplies the key
   back through `PDS_OAUTH_KEYS_JWK_SET`. The
   PDS publishes the same key afterwards. The PDS's key variable uses
   `generate=false`, so a failed adoption fails the play rather than minting a
   different key.

6. **Rotation is `scn-config`'s Signing Keys entry** (`nonint show-keys |
   rotate-key <name> | retire-key <name>`, over `rotate-key.yml`). Rotate moves
   current to previous and generates a new current; retire deletes previous.
   Each takes effect on the service's next provision. One rotation at a time.
   `signing_key_registry` in `group_vars/all/main.yml` lists every rotatable
   key, the service that uses it and what retiring costs.

7. **Each service keeps the previous key working in the way its protocol
   needs.** A token verifier needs the old public key published until tokens
   it signed expire. An atproto confidential client needs more: the
   authorization server ties a session to the key that authenticated it, so a
   refresh must be signed with that key. Corliss records the kid per session
   (`AtprotoToken.client_kid`, v1.4.1) and refreshes with it;
   `@atproto/oauth-client`, which scn-chat uses, does the same on its own.

## Consequences

- A new service that signs with a key adds two lines to `group_vars` and one
  entry to `signing_key_registry`; [adding-a-service.md](../adding-a-service.md)
  has the recipe. No per-service generator, no build toolchain on the control
  node.
- Retiring the previous key of an atproto client ends the sessions still on
  it, and those members sign in again. Rotating is safe; retiring is the step
  with a cost, and the menu says what it is before it runs.
- The PDS's OAuth key is now in the Tier-1 backup.
- The old `pds_oauth_jwk_set` override is no longer read. Its keys are adopted
  and the file is renamed `pds_oauth_jwk_set.adopted`, kept rather than
  deleted. A set with more than two keys is refused, since only a current and
  a previous key have somewhere to go.
